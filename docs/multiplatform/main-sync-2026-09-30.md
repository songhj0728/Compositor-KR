## v12 and Layer Style audit

New shared-data candidates: EffectContour, EffectPattern, BevelEffect (including
Style/Technique), SatinEffect, PatternOverlayEffect. Existing six effects add
optional blend/contour/spread/choke/centered/fromCenter fields. LayerEffects adds
three slots and Fill Opacity; the exact dependency inventory is in
[document-model-inventory.md](document-model-inventory.md).

The package layout/UUID/PNG mapping is unchanged. Reader supports1–12; save writes
11 without stored v12 fields, 12 with them. Presence matters even when a value is
disabled/default. A current12 manifest can save as11; the in-memory snapshot's
version is therefore not necessarily the written version. Explicit older versions
are validated rather than silently upgraded. Shape fill/stroke/strokeOutside is
additive metadata; legacy missing outside flag preserves inside-stroke appearance.

Core keeps all style settings and Fill Opacity, separately from layer opacity.
The fixed style stack blends within one layer. Renderer gets mask-derived source
coverage, style settings and layer-local pattern origin. Legacy effects keep their
Metal path; active full styles use the new floating-point CPU renderer. This does
not choose a Windows GPU API or move CPU rendering into the model.

History implementation is unchanged: value snapshots, image sharing and equality
including effects. Dialog preview mutates live fields; OK restores originals then
records one Layer Style entry, Cancel restores with no entry. New LayerStyleTests
checks this plus undo/redo. Existing duplicate/whole-layer clipboard/cross-document
copy carries nested effects values and remaps layer IDs. Grouping remains
pass-through with child styles retained; no new folder-style feature is added.
Dedicated new-style duplicate/paste/group matrices have not been added or run.

PSD service writes editable text/style/fill where representable, reads supported
styles, and reports raster fallback for procedural patterns/texture or requested
flattening. It does not establish full Photoshop feature or appearance parity.

New question Q16: canStartProjectOperation and ProjectController save preparation
do not exclude/finish layerStyle, unlike undo/layer-edit gating. Characterize
preview→save→Cancel/OK and saved-state behavior before a future transaction adapter.
This sync preserves the main behavior, with no speculative fix.
